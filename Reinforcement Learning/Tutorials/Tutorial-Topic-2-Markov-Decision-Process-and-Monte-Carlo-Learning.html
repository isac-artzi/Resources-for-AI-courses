Topic 2 — Markov Decision Process and Monte Carlo Learning

Topic 1 handed value iteration a transition kernel and then took it away again for Q-learning. This topic makes that hand-off the subject. We derive the Bellman expectation equation, prove the policy improvement theorem, run value iteration and policy iteration side by side on the same 5×5 grid and count what each actually costs, then delete the model and estimate the same value function from sampled returns alone — first-visit and every-visit, on-policy and off-policy — and measure how many episodes it takes for the estimate to become indistinguishable from the exact answer.

1. The MDP, restated with the model in hand

The object under study is unchanged from Topic 1 — the five-tuple

\[ \mathcal{M} = \langle \mathcal{S},\, \mathcal{A},\, P,\, R,\, \gamma \rangle, \qquad P(s'\mid s,a) = \Pr(S_{t+1}=s' \mid S_t=s, A_t=a), \]

with \(R(s,a,s')\) the reward received on the transition and \(\gamma \in [0,1)\) the discount factor. What changes in this topic is possession. In Topic 1 the tuple was a description of a problem the agent had to learn about. Here you own \(P\) and \(R\) as arrays in memory: envs/gridworld.py exposes an explicit transition-probability matrix, and the planner reads it.

Start from the definition of the state-value function and split the return at its first term. This is the entire derivation; everything else is bookkeeping.

\[ v_\pi(s) \;=\; \mathbb{E}_\pi\!\left[ G_t \mid S_t = s\right], \qquad G_t \;=\; R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots \]

Factor \(\gamma\) out of everything after the first reward:

\[ G_t \;=\; R_{t+1} + \gamma\big( R_{t+2} + \gamma R_{t+3} + \cdots \big) \;=\; R_{t+1} + \gamma\, G_{t+1}. \]

That identity is exact and holds sample by sample, not merely in expectation. Substituting it and using linearity of expectation,

\[ v_\pi(s) \;=\; \mathbb{E}_\pi\!\left[ R_{t+1} + \gamma G_{t+1} \mid S_t = s\right]. \]

Now expand the expectation over the two things that happen next: the policy draws an action, and the kernel draws a successor. Conditioning on \(S_{t+1}=s'\) and using the Markov property — which says \(\mathbb{E}_\pi[G_{t+1}\mid S_t=s, A_t=a, S_{t+1}=s'] = \mathbb{E}_\pi[G_{t+1}\mid S_{t+1}=s'] = v_\pi(s')\), because nothing before \(s'\) carries information about what follows it — gives the Bellman expectation equation:

\[ \boxed{\;v_\pi(s) \;=\; \sum_{a} \pi(a\mid s) \sum_{s'} P(s'\mid s,a)\Big[ R(s,a,s') + \gamma\, v_\pi(s') \Big].\;} \]

Read the three factors in order: \(\pi(a\mid s)\) is the agent's choice, \(P(s'\mid s,a)\) is the environment's, and the bracket is one step of reward plus the discounted value of where you land. The action-value form drops the outer average, since the action is given:

\[ q_\pi(s,a) \;=\; \sum_{s'} P(s'\mid s,a)\Big[ R(s,a,s') + \gamma\, v_\pi(s') \Big], \qquad v_\pi(s) = \sum_a \pi(a\mid s)\, q_\pi(s,a). \]

For a finite MDP this is a system of \(|\mathcal{S}|\) linear equations in \(|\mathcal{S}|\) unknowns, \(v_\pi = r_\pi + \gamma P_\pi v_\pi\), whose solution is \(v_\pi = (I - \gamma P_\pi)^{-1} r_\pi\). The matrix is invertible for every \(\gamma < 1\) because \(\gamma P_\pi\) has spectral radius at most \(\gamma\). So policy evaluation is, in principle, a single linear solve.

Why we iterate a fixed point instead of inverting the matrix we just wrote down. The closed form is \(O(|\mathcal{S}|^3)\) and requires \(P_\pi\) to be materialised as a dense \(|\mathcal{S}|\times|\mathcal{S}|\) array. On the 25-state grid in this topic that is trivial and you could genuinely use np.linalg.solve. It stops being trivial one topic later: a coarse discretisation of CartPole with six bins per dimension is \(6^4 = 1296\) states, and the same kernel written densely is 1.7 million entries of which almost all are zero. Iterative evaluation costs \(O(\text{nonzeros})\) per sweep and never forms the inverse, it warm-starts from the previous answer — which is exactly what makes policy iteration cheap after its first round — and it degrades gracefully into the sampled updates of §4, which the linear solve does not. The closed form is the better proof; the iteration is the better algorithm, and the reason is sparsity and reuse rather than arithmetic count.

What owning \(P\) actually buys

Q-learning in Topic 1 replaced the inner sum \(\sum_{s'} P(s'\mid s,a)[\cdot]\) with a single sampled successor and took a small step toward it. Compare the two updates term by term and three differences fall out.

  • Exact expectations, hence no sampling variance. A planning backup evaluates the full sum over successors. Its only error is the error already sitting in \(V\); it introduces none of its own. A sampled backup carries the variance of \(R + \gamma V(S')\), which is why it needs a step size \(\alpha\) and why the Robbins–Monro conditions exist at all. A planner has no learning rate because it does not need one.
  • Backups anywhere, in any order. Experience arrives in trajectories: to update a state you must first reach it. A planner updates any state at any moment, so it can sweep in whatever order converges fastest and can reach states no policy would ever visit. That freedom is the whole content of §3.
  • Counterfactuals for free. \(q_\pi(s,a)\) for an action the policy never takes is one sum away. Without \(P\), the only way to learn about an untaken action is to take it — which is why exploration is a topic in model-free control and not in planning.

The cost is that \(P\) must be correct. A planner returns the optimal policy for the model it was given, and it does so with total confidence and no diagnostic that would reveal the model to be wrong. That asymmetry is the client's question in the Policy Lab brief, and it is not settled by preferring one method: it is settled by measuring the gap on the environment you actually face.

Why the five-tuple is a modelling commitment and not a transcription of reality. Writing \(P\) down forces three decisions that a model-free agent leaves implicit and therefore never has to defend. First, the state alphabet: the 5×5 grid has 25 states because you decided position is sufficient, and that decision is what makes the kernel Markov. Second, the support: every successor you failed to enumerate has been assigned probability zero, and a planner will exploit a zero-probability catastrophe with no hesitation whatever. Third, the reward: \(R\) is not measured, it is authored, and the optimal policy is optimal only with respect to what you wrote. The Monte Carlo learner in §4 inherits the first commitment and escapes the second and third — it can only be as wrong as the environment it sampled. This is the honest form of the "plan or learn" argument, and it is stronger than either consultant's version of it in the product brief.

2. Evaluation, improvement, and the improvement theorem

Two operations generate every dynamic-programming algorithm in this topic.

Policy evaluation turns the Bellman expectation equation into an assignment and iterates it:

\[ V_{k+1}(s) \;\leftarrow\; \sum_a \pi(a\mid s) \sum_{s'} P(s'\mid s,a)\big[ R(s,a,s') + \gamma V_k(s') \big]. \]

The operator \(T_\pi\) is a \(\gamma\)-contraction in the max norm — \(\lVert T_\pi V - T_\pi U\rVert_\infty \le \gamma \lVert V - U \rVert_\infty\), because the difference passes through a convex combination of successor values and is then multiplied by \(\gamma\) — so \(V_k \to v_\pi\) geometrically from any start.

Policy improvement reads a new policy off the values just computed:

\[ \pi'(s) \;=\; \arg\max_a\, q_\pi(s,a) \;=\; \arg\max_a \sum_{s'} P(s'\mid s,a)\big[R(s,a,s') + \gamma v_\pi(s')\big]. \]

The policy improvement theorem

Theorem. Let \(\pi\) and \(\pi'\) be deterministic policies such that

\[ q_\pi(s, \pi'(s)) \;\ge\; v_\pi(s) \qquad \text{for every } s \in \mathcal{S}. \]

Then \(v_{\pi'}(s) \ge v_\pi(s)\) for every \(s\). If the first inequality is strict at some state, the second is strict at that state.

Proof. The premise compares one step of \(\pi'\) followed by \(\pi\) forever against \(\pi\) from the start. Apply it repeatedly, peeling one more step of \(\pi'\) off the front each time:

\[ \begin{aligned} v_\pi(s) &\le q_\pi(s,\pi'(s)) \\ &= \mathbb{E}_{\pi'}\!\big[ R_{t+1} + \gamma\, v_\pi(S_{t+1}) \,\big|\, S_t = s \big] \\ &\le \mathbb{E}_{\pi'}\!\big[ R_{t+1} + \gamma\, q_\pi(S_{t+1}, \pi'(S_{t+1})) \,\big|\, S_t = s \big] \\ &= \mathbb{E}_{\pi'}\!\big[ R_{t+1} + \gamma R_{t+2} + \gamma^2 v_\pi(S_{t+2}) \,\big|\, S_t = s \big] \\ &\;\;\vdots \\ &\le \mathbb{E}_{\pi'}\!\big[ R_{t+1} + \gamma R_{t+2} + \cdots + \gamma^{n-1} R_{t+n} + \gamma^{n} v_\pi(S_{t+n}) \,\big|\, S_t = s \big]. \end{aligned} \]

Each inequality is the premise applied at the state reached at that step; each equality is one Bellman expansion under \(\pi'\). The subscript on the expectation is \(\pi'\) throughout because every action that has been peeled off was chosen by \(\pi'\). Now let \(n \to \infty\). With bounded rewards, \(|\gamma^n v_\pi(S_{t+n})| \le \gamma^n R_{\max}/(1-\gamma) \to 0\), and the truncated sum converges to \(G_t\) under \(\pi'\), so the right-hand side converges to \(\mathbb{E}_{\pi'}[G_t \mid S_t=s] = v_{\pi'}(s)\). Hence \(v_\pi(s) \le v_{\pi'}(s)\). \(\;\blacksquare\)

The greedy policy of the definition above satisfies the premise automatically, since \(\max_a q_\pi(s,a) \ge \sum_a \pi(a\mid s) q_\pi(s,a) = v_\pi(s)\) — a maximum is at least an average. And if greedification changes nothing, then \(v_\pi(s) = \max_a q_\pi(s,a)\) for all \(s\), which is the Bellman optimality equation; its unique solution is \(v_*\), so \(\pi\) is optimal. Policy iteration therefore stops only at an optimal policy, and since there are finitely many deterministic policies and each round strictly improves at least one state, it stops after finitely many rounds.

Why the theorem has to be proved by telescoping rather than by the obvious one-step argument. The premise is a statement about \(q_\pi\) — the value of deviating once and then reverting to \(\pi\). The conclusion is a statement about \(v_{\pi'}\) — the value of deviating forever. Those are different quantities, and the gap between them is exactly where the intuition "each state got better, so the policy got better" fails in general: changing the policy changes the state distribution, and a change that helps at \(s\) could in principle route the agent into states where it does worse. The telescoping argument closes that gap by never assuming anything about the new state distribution; it re-applies the same one-step premise at whichever state \(\pi'\) actually reaches, so the induction survives the distribution shift it creates. This is the same structural difficulty that policy-gradient methods in Topic 3 handle with a trust region, for the same reason.

Why the ordering is only partial

Define \(\pi \succeq \pi'\) to mean \(v_\pi(s) \ge v_{\pi'}(s)\) for every \(s\). This relation is reflexive, transitive, and antisymmetric on value functions, but it is not total: there exist \(\pi, \pi'\) with \(v_\pi(s_1) > v_{\pi'}(s_1)\) and \(v_\pi(s_2) < v_{\pi'}(s_2)\), and then neither \(\pi \succeq \pi'\) nor \(\pi' \succeq \pi\). Such policies are incomparable: no amount of further evaluation will rank them, because the ranking does not exist.

A two-state example suffices. Let \(s_1\) and \(s_2\) be two doors leading to two different terminal payoffs, with actions left and right. Suppose from \(s_1\), left is worth 5 and right 2; from \(s_2\), left is worth 1 and right 4. The policy "always left" beats "always right" at \(s_1\) and loses at \(s_2\). They are incomparable, and the partial order is silent.

This does not obstruct policy iteration, and the reason is worth stating precisely: greedification never produces an incomparable policy. It produces a policy that satisfies the premise of the theorem at every state simultaneously, so the conclusion holds at every state simultaneously, so \(\pi' \succeq \pi\) by construction. The algorithm walks a chain in the partial order, never a branch. Incomparability matters instead when you are comparing two policies that were not produced from one another this way — two students' agents, two hyperparameter settings, a planner against a learner. Then "which is better" is not a well-posed question until you say better where, which in practice means committing to a start-state distribution \(\mu\) and comparing the scalar \(\sum_s \mu(s) v_\pi(s)\). Every existence theorem for an optimal policy is a statement that the greedy chain terminates, not a statement that the partial order is total.

3. Value iteration and policy iteration: two schedules over one backup

Policy iteration alternates the two operations to convergence:

\[ \pi_0 \xrightarrow{\;E\;} v_{\pi_0} \xrightarrow{\;I\;} \pi_1 \xrightarrow{\;E\;} v_{\pi_1} \xrightarrow{\;I\;} \pi_2 \;\cdots\; \pi_* \xrightarrow{\;E\;} v_*. \]

Value iteration refuses to wait for \(E\) to finish. It performs exactly one evaluation sweep and folds the improvement step into it, which is algebraically the same as applying the Bellman optimality operator:

\[ V_{k+1}(s) \;\leftarrow\; \max_a \sum_{s'} P(s'\mid s,a)\big[R(s,a,s') + \gamma V_k(s')\big]. \]

The two are endpoints of one family. Truncate policy evaluation at \(m\) sweeps: \(m = \infty\) is policy iteration, \(m = 1\) is value iteration, and any \(m\) in between is modified policy iteration, which converges for all of them. What differs is only the schedule on which the same backups are applied — this is the content of the phrase "generalised policy iteration."

The cost accounting has two units and they point in opposite directions, which is why the comparison confuses people.

  • Outer iterations. Policy iteration terminates in a number of rounds bounded by the number of deterministic policies, but in practice needs a handful — typically three to six even on large problems. Value iteration needs enough sweeps for the contraction to grind the residual down: \(\gamma^k \lVert V_0 - v_*\rVert_\infty < \varepsilon\), so \(k \approx \ln \varepsilon / \ln \gamma\), which grows like \(1/(1-\gamma)\).
  • Elementary backups. Count one evaluation of \(q(s,a)\) as the unit. A value-iteration sweep costs \(|\mathcal{S}||\mathcal{A}|\) of them. A policy-evaluation sweep for a deterministic policy costs only \(|\mathcal{S}|\), since there is one action per state — but a policy-iteration round runs many such sweeps and then pays \(|\mathcal{S}||\mathcal{A}|\) for the improvement. The cheap iterations are the ones you need many of.

Why "policy iteration converges in fewer iterations" is true and almost always quoted misleadingly. The counter above shows policy iteration finishing in a small number of outer rounds against value iteration's tens — and simultaneously spending more elementary backups to get there, because its first evaluation solves \(v_{\pi_0}\) to full accuracy for a policy that is about to be thrown away. Two consequences follow. The first is that "fewer iterations" is a claim about a unit of work that is not constant across the two algorithms, and any cost comparison that does not normalise it is empty. The second is the practical fix: set the evaluation depth to 5 in the selector. Modified policy iteration keeps the small round count and drops most of the wasted precision, and on this MDP it beats both endpoints on total backups. That is why the sensible default in a production planner is neither \(m=1\) nor \(m=\infty\), and why your engineering report should quote backups rather than iterations when it compares the planner's computational profile against the linear-programming formulation.

Discounting is not only a modelling choice; it is the algorithm's condition number. The contraction bound predicts \(k \approx \ln\varepsilon/\ln\gamma\) sweeps, so it forecasts that moving \(\gamma\) from \(0.9\) to \(0.99\) multiplies the sweep count by \(\ln 0.9 / \ln 0.99 \approx 10.5\) — the same factor by which the effective horizon \(1/(1-\gamma)\) grows. Two things are worth testing rather than believing. The bound is worst-case over all MDPs with that \(\gamma\), and on an episodic problem it is loose by an order of magnitude, because the \(k\)-step operator contracts by \(\gamma^k\) multiplied by the probability of not yet having been absorbed. And \(\gamma\) changes the answer, not only the time taken to compute it: at a critical \(\gamma\) the \(\arg\max\) flips in some state and the optimal policy changes shape. Why linear programming is the third way to solve this, and what it costs. The Bellman optimality equation is equivalent to a linear program: minimise \(\sum_s \mu(s) V(s)\) subject to \(V(s) \ge \sum_{s'} P(s'|s,a)[R(s,a,s') + \gamma V(s')]\) for every pair \((s,a)\), with any strictly positive \(\mu\). The constraints force \(V \ge T V\), the objective pushes \(V\) down, and the unique point satisfying both is \(v_*\); the optimal dual variables are the discounted state-visitation frequencies of §6. The LP has \(|\mathcal{S}|\) variables and \(|\mathcal{S}||\mathcal{A}|\) constraints and is solvable in polynomial time in those — which is a genuinely stronger guarantee than value iteration has, since value iteration's sweep count depends on \(\gamma\) and on the required accuracy, and is only weakly polynomial. In practice the LP is far slower on any MDP large enough to matter, because interior-point and simplex methods do not exploit the sparse, structured backups that a sweep is made of and cannot warm-start from the previous policy the way policy iteration does. The reason to know the formulation is not that you will run it: it is that constraints and duals are how you add side conditions — safety budgets, throughput floors — that no Bellman backup can express. Your engineering report is asked for exactly this comparison.

4. Monte Carlo policy evaluation

Delete \(P\). The definition \(v_\pi(s) = \mathbb{E}_\pi[G_t \mid S_t = s]\) is still a statement about an expectation, and an expectation can be estimated by an average. That is the whole of Monte Carlo policy evaluation: run complete episodes under \(\pi\), compute the realised return from each visit to \(s\), and average.

Two accounting rules are available when a state occurs more than once in an episode.

  • First-visit MC. Use only the return following the first occurrence of \(s\) in each episode. Each episode contributes at most one sample per state.
  • Every-visit MC. Use the return following every occurrence. One episode may contribute several samples for the same state.

Both are consistent, but for different reasons, and the difference is exactly the bias–variance question.

First-visit. Fix \(s\). Across episodes, the first-visit returns \(G^{(1)}, G^{(2)}, \dots\) are independent — different episodes share no randomness — and each is distributed as \(G_t \mid S_t = s\) under \(\pi\), whose mean is \(v_\pi(s)\) by definition. So the sample mean of \(n\) of them is an unbiased estimator at every \(n\), and by the strong law of large numbers it converges almost surely to \(v_\pi(s)\). Its standard error is \(\sigma(s)/\sqrt{n}\) with \(\sigma^2(s) = \operatorname{Var}_\pi(G_t \mid S_t = s)\). This is the cleanest consistency argument in reinforcement learning: it is just the LLN, with no contraction, no step size, and no bootstrapping.

Every-visit. The returns from the second and later visits within one episode are not independent of the first — they share the same tail of the same trajectory — and, worse, the number of samples an episode contributes is itself random and correlated with the returns. A state that happens to be revisited many times is a state the trajectory lingered in, and lingering is not independent of the return. So the every-visit average is a ratio of two dependent random quantities and is biased at finite \(n\). The bias is \(O(1/n)\) in the number of episodes while the standard error is \(O(1/\sqrt{n})\), so the bias is dominated asymptotically and vanishes; every-visit MC is consistent, converging almost surely to \(v_\pi(s)\), but it is not unbiased at any finite sample size. In exchange it extracts more samples per episode, which usually lowers variance — most visibly in long episodes with heavy revisiting.

Neither dominates. Which is better on your problem is an empirical question about episode length, revisit structure and return variance, and it is the question the next demo is built to answer honestly.

5. Monte Carlo control

Evaluation is not the goal; improvement is. Generalised policy iteration works without a model, with one forced change: you must estimate \(q_\pi\), not \(v_\pi\). Greedification from \(v\) requires \(\arg\max_a \sum_{s'} P(s'|s,a)[\cdot]\), which needs the kernel. Greedification from \(q\) is \(\arg\max_a Q(s,a)\), which needs nothing. Removing \(P\) therefore promotes the action-value function from a convenience to a necessity.

That change creates a problem the planner did not have. \(Q\) has \(|\mathcal{S}||\mathcal{A}|\) entries and a deterministic policy generates data for exactly \(|\mathcal{S}|\) of them. The remaining entries keep whatever they were initialised to, and \(\arg\max\) over a row that is mostly stale initialisation is not an improvement step — it is noise. The Monte Carlo control loop needs every state–action pair to keep receiving data, and there are exactly two on-policy ways to arrange it.

  • Exploring starts. Begin each episode at a pair \((s_0,a_0)\) drawn with non-zero probability over all pairs, then follow \(\pi\). Every pair is then visited infinitely often in the limit, and the policy may stay deterministic. This is the assumption under which Monte Carlo ES is proved to converge, and it is what train/monte_carlo.py implements for the Policy Lab.
  • Soft policies. Require \(\pi(a\mid s) > 0\) for all \(a\) and \(s\). The canonical family is \(\varepsilon\)-greedy: \(\pi(a\mid s) = 1-\varepsilon+\varepsilon/|\mathcal{A}|\) for the greedy action and \(\varepsilon/|\mathcal{A}|\) otherwise. Exploration is then carried by the policy itself rather than by the reset, and no special start distribution is needed.

The improvement theorem still applies to the soft case, with the maximum replaced by the best \(\varepsilon\)-soft mixture. Writing \(\pi'\) for the \(\varepsilon\)-greedy policy with respect to \(q_\pi\),

\[ q_\pi(s,\pi'(s)) \;=\; \frac{\varepsilon}{|\mathcal{A}|}\sum_a q_\pi(s,a) \;+\; (1-\varepsilon)\max_a q_\pi(s,a) \;\ge\; \frac{\varepsilon}{|\mathcal{A}|}\sum_a q_\pi(s,a) + (1-\varepsilon)\sum_a \frac{\pi(a\mid s) - \varepsilon/|\mathcal{A}|}{1-\varepsilon}\, q_\pi(s,a) \;=\; v_\pi(s), \]

where the inequality replaces the maximum by an average against the non-negative weights \((\pi(a|s)-\varepsilon/|\mathcal{A}|)/(1-\varepsilon)\), which sum to one precisely because \(\pi\) is \(\varepsilon\)-soft. The premise of the theorem holds, so \(v_{\pi'} \ge v_\pi\), and the fixed point of this scheme is the best \(\varepsilon\)-soft policy — not \(\pi_*\). That last clause is the price: with a fixed \(\varepsilon\) you converge to the optimum of a constrained policy class, and the gap does not close unless \(\varepsilon \to 0\) on a schedule that still visits everything infinitely often. This is the GLIE condition, and it is the same schedule Topic 1 imposed on \(\varepsilon\)-greedy Q-learning.

Why exploring starts is the assumption you cannot ship, and what that implies. Exploring starts requires the ability to reset the environment into an arbitrary state and force an arbitrary first action. A simulator grants this — env.reset(options={"state": s}) is three lines in a custom Gymnasium environment, which is why it is the right choice for a laboratory whose purpose is to isolate the estimator from the exploration problem. Nothing else grants it. You cannot place a physical robot in an arbitrary pose, you cannot start a recommender session from an arbitrary user history, and in a logged-data setting there is no reset at all. The assumption's real function is theoretical: it separates "does this algorithm converge given coverage?" from "how do we obtain coverage?", and answering the first cleanly is what allows the second to be attacked separately — by soft policies here, and by off-policy correction in §6, which is the only one of the three that survives contact with data you did not collect.

6. Off-policy Monte Carlo and importance sampling

Both mechanisms in §5 change the behaviour of the agent in order to learn. Off-policy methods refuse to: a behaviour policy \(b\) generates the data, a target policy \(\pi\) is the one being evaluated, and the estimate is corrected mathematically rather than by acting differently. The requirement is coverage: \(\pi(a\mid s) > 0 \implies b(a\mid s) > 0\).

The correction is a change of measure. The probability of a trajectory \(A_t, S_{t+1}, A_{t+1}, \dots, S_T\) starting from \(S_t=s\) is

\[ \Pr\{\,\cdot\, \mid S_t, \pi\} = \prod_{k=t}^{T-1} \pi(A_k\mid S_k)\, P(S_{k+1}\mid S_k, A_k), \]

so the ratio of the two trajectory probabilities is

\[ \rho_{t:T-1} \;=\; \frac{\prod_{k=t}^{T-1} \pi(A_k\mid S_k)\,P(S_{k+1}\mid S_k,A_k)}{\prod_{k=t}^{T-1} b(A_k\mid S_k)\,P(S_{k+1}\mid S_k,A_k)} \;=\; \prod_{k=t}^{T-1} \frac{\pi(A_k\mid S_k)}{b(A_k\mid S_k)}. \]

Every transition probability cancels, because both policies act in the same environment. The ratio is computable from the two policies and the observed actions alone — the model is not needed, which is what makes the technique available to a model-free learner at all.

Because \(\mathbb{E}_b[\rho_{t:T-1} G_t \mid S_t=s] = \mathbb{E}_\pi[G_t \mid S_t = s] = v_\pi(s)\), the ordinary importance-sampling estimator over \(n\) episodes is unbiased:

\[ V_{\text{OIS}}(s) \;=\; \frac{1}{n}\sum_{i=1}^{n} \rho^{(i)} G^{(i)}. \]

The weighted importance-sampling estimator normalises by the ratios instead of by the count:

\[ V_{\text{WIS}}(s) \;=\; \frac{\sum_{i=1}^n \rho^{(i)} G^{(i)}}{\sum_{i=1}^n \rho^{(i)}}. \]

The trade is sharp. \(V_{\text{OIS}}\) is unbiased but its variance is unbounded: it is a product of \(T\) ratios, so it is log-normal-ish in \(T\) and a single episode with a large \(\rho\) dominates the average. In the extreme, if the return has finite variance but \(\rho\) does not, the estimator's variance is literally infinite and its sample mean has no central limit theorem. \(V_{\text{WIS}}\) is a weighted average of observed returns with weights summing to one, so it is a convex combination of the \(G^{(i)}\) and can never leave their range; its variance is bounded and in practice dramatically smaller. It is biased — from one episode it returns \(G^{(1)}\) regardless of \(\rho^{(1)}\), i.e. \(\mathbb{E}_b[V_{\text{WIS}}] = v_b\) at \(n=1\) — but the bias falls as \(O(1/n)\) and it is consistent. Weighted IS is the default in every practical off-policy estimator for this reason.

The diagnostic that predicts trouble before it appears in the estimate is the effective sample size

\[ n_{\text{eff}} \;=\; \frac{\left(\sum_i \rho^{(i)}\right)^2}{\sum_i \left(\rho^{(i)}\right)^2} \;\in\; [1, n], \]

the number of equally-weighted episodes carrying the same information as your \(n\) unequally-weighted ones. It equals \(n\) when \(b = \pi\) and collapses toward 1 as they separate.

Why the estimator with the guaranteed-correct expectation is the one you must not ship. Unbiasedness is a statement about an average over infinitely many replications of the whole experiment. You will run the experiment once. What governs the error of that single run is the variance, and ordinary importance sampling trades a bias of exactly zero for a variance that grows multiplicatively in the horizon — a four-step problem with a ratio bounded by \(10/3\) per step already admits weights above 100. Weighted importance sampling accepts a bias that shrinks like \(1/n\) in return for a variance that cannot exceed the spread of the returns themselves, because the estimate is a convex combination of them. Mean squared error is bias squared plus variance, and on any realistic budget the second term is the one with the exponent in it. The general principle is the one that also justifies clipping in Topic 4's PPO and reward-model normalisation in Topic 6: a bounded, slightly wrong estimator beats an unbounded, exactly-right one whenever the sample is finite — and it is always finite.

Where your data actually comes from

Importance sampling reweights trajectories. The corresponding statement about states is the discounted state-visitation frequency: for a start distribution \(\mu\),

\[ d^\pi_\gamma(s) \;=\; (1-\gamma)\sum_{t=0}^{\infty} \gamma^{t}\, \Pr\{S_t = s \mid S_0 \sim \mu, \pi\}, \qquad \sum_s d^\pi_\gamma(s) = 1. \]

The factor \((1-\gamma)\) normalises it into a probability distribution. It is the measure under which every discounted objective is secretly an average: \(\sum_s \mu(s) v_\pi(s) = \frac{1}{1-\gamma}\, \mathbb{E}_{s \sim d^\pi_\gamma,\, a\sim\pi}[R(s,a)]\), and it is the distribution that appears in the policy gradient theorem in Topic 3 and as the dual variables of the linear program in §3. Two readings of \(\gamma\) meet here. Interpreting \(1-\gamma\) as a per-step termination probability makes \(d^\pi_\gamma\) literally the distribution of the state you are standing in when the episode is cut off — which is how the demo below simulates it, without any discounting arithmetic at all.

Why this diagram is the exploration–exploitation trade-off drawn in state space. At \(\gamma = 0.5\) roughly two-thirds of all discounted weight sits on the start state: the agent is being scored almost entirely on what it does in the first two steps, so anything it could learn about the far end of the chain is worth almost nothing to the objective, and an optimiser will not pay to explore there. At \(\gamma = 0.99\) the weight has spread out to nearly the stationary distribution and the far states carry real mass — the objective now rewards long-run positioning, and exploration that reaches distant states pays for itself. This is why raising \(\gamma\) does not merely "make the agent more patient" as a matter of preference: it moves the measure your gradient, your Bellman residual and your reported return are all averages against. It is also the reason off-policy evaluation degrades faster than the per-step ratios suggest. If \(b\) and \(\pi\) induce different visitation distributions, the states where you have the most data are not the states where \(\pi\) spends its time, and no reweighting can create samples in a region \(b\) never entered.

Why one preprocessing module, and why the two learners use different parts of it

shared/preprocess.py owns every transformation between raw environment output and learner input: one-hot state encoding, the discretisation scheme for a continuous observation, reward clipping, and return normalisation. Every learner imports from it; nothing transforms inline. The reason the module exists is not tidiness — it is that a planner and a sampler consume different objects, and the differences are not cosmetic.

  • The planner never sees a sample. Value iteration consumes \(P\) and \(R\) as arrays indexed by an integer state id. One-hot encoding buys it nothing: \(\arg\max_a\) over a table is an integer index, and expanding 25 states into 25-dimensional basis vectors would only add a matrix multiply to a lookup. Discretisation, by contrast, it needs before it can exist at all — a continuous observation space has no transition matrix, so the bin edges chosen in discretize() literally define the MDP the planner solves.
  • Reward clipping changes the MDP, not the pipeline. Clipping to \([-1,1]\) is a variance-control measure for a sampled learner. Applied to the planner it changes \(R\), and therefore changes \(v_*\) and possibly \(\arg\max_a q_*\). So it must be applied to both or to neither: clip for the Monte Carlo learner and not for the planner, and your RMSE curve is measuring the distance between solutions to two different problems and will not converge to zero no matter how many episodes you run. This is the single most common way the Topic 2 convergence plot comes out wrong.
  • Return normalisation is meaningless for the planner and invertible for the learner. The planner never forms a return. The Monte Carlo learner does, and standardising returns stabilises the running averages — but the normalised estimate is on a different scale from \(v_*\), so the transformation must be inverted before the RMSE against the exact solution is computed. Keep the mean and standard deviation used; store them next to the artifact.
  • One-hot is for Topic 3. It is in the module now because a linear or neural policy will need it, and because a transformation that trains on one encoding and serves on another is a bug that no unit test on the model can catch. The transformation applied at training must provably be the one applied at serving; that provability is what a single imported module gives you and inline code does not.
# shared/preprocess.py — every transformation between environment and learner lives here
import numpy as np
N_STATES, N_ACTIONS = 25, 4

def one_hot(s: int) -> np.ndarray:                # Topic 3 needs this; the planner never calls it
    x = np.zeros(N_STATES, dtype=np.float32); x[s] = 1.0
    return x

def discretize(obs, edges) -> int:                # continuous obs -> tabular index; DEFINES the MDP
    idx = [int(np.digitize(o, e)) for o, e in zip(obs, edges)]
    return int(np.ravel_multi_index(idx, [len(e) + 1 for e in edges]))

def clip_reward(r: float, lo=-1.0, hi=1.0) -> float:
    return float(np.clip(r, lo, hi))          # CHANGES R: apply to planner AND learner, or neither

def normalize_returns(G: np.ndarray):
    mu, sd = float(G.mean()), float(G.std() + 1e-8)
    return (G - mu) / sd, (mu, sd)             # return the constants; RMSE needs the inverse

The off-policy demo makes a schema demand of its own. For a reader to recompute your importance-sampling variance from your data alone — DQ 3(d) — the episode row must carry enough to reconstruct \(\rho\): the behaviour policy's parameters in force, the target policy identifier, the realised return, and the episode's ratio or the per-step action log-probabilities under both policies.
